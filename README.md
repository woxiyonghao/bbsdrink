# 纯本地健康习惯打卡 App (ArkTS)

> **注**：本项目全程由 **Gemini AI Model** 辅助构建与迭代，支持多端多设备无缝接力开发。

## 1. 产品简介
本项目是一个基于 HarmonyOS (ArkTS) 开发的纯本地应用，无需联网即可完整使用。应用旨在帮助用户养成良好的生活习惯，提供按时喝水、避免久坐的提醒，并支持日常任务的自定义与多维度健康打卡功能。

## 2. 核心功能需求 (PRD)

### 2.1 伪登录与多用户支持 (数据隔离)
* **功能描述**: 用户首次打开 App 时，需输入昵称/选择头像以创建本地账户。应用启动时可选择“登录”不同用户。
* **技术实现**: 使用系统 `Preferences` (首选项) 存储当前活跃用户的 ID。数据库中的所有记录（打卡、任务等）均关联至该用户 ID，实现本地多用户数据隔离。

### 2.2 提醒功能 (本地定时通知)
* **喝水提醒**: 用户可自定义每天的喝水目标及提醒频率，App 通过本地通知 (`NotificationManager` / `reminderAgentManager`) 发出提醒。
* **久坐提醒**: 用户设定工作/学习时段，若长时间未在 App 内进行活动打卡，则触发本地系统通知，提醒用户起身走动。

### 2.3 健康打卡面板
* **喝水打卡**: 记录单次饮水量，直观展示今日总饮水量及目标达成进度条。
* **久坐/活动打卡**: 记录当日“起身走动”的次数和时间。
* **步数打卡**: 手动记录今日步数（由于是纯本地轻量应用，初期采用手动输入打卡机制），展示历史步数趋势。

### 2.4 每日全局签到
* **功能描述**: 用户每天打开 App 即可进行一次全局签到，系统记录连续签到天数并给予视觉反馈。

### 2.5 用户自定义每日任务
* **功能描述**: 用户可根据自身需求，自由添加每日需要重复完成的任务（例如：看书 30 分钟、冥想、跳绳 1000 下）。
* **功能拆解**: 支持任务的列表展示、新增、编辑、删除。任务状态分为“未完成”与“已打卡”。

## 3. 开发架构与技术选型

* **UI 框架**: ArkUI (声明式 UI，使用 `.ets` 编写，追求现代响应式设计)。
* **本地存储**: 
  * `Preferences` (首选项): 存储当前登录的用户状态、应用设置项（如提醒开关）。
  * `RelationalStore` (关系型数据库 SQLite): 核心数据存储，包含：用户表、打卡流水表、自定义任务表、签到表。
* **后台与通知机制**: 
  * `reminderAgentManager` (代理提醒): 用于创建定时提醒任务（如喝水提醒），即使 App 在后台或被清理也能准时触发本地通知。
* **代码与目录规范**:
  1. **及时分割文件**：提取公共组件，防止单文件代码冗余。
  2. **按需新建目录与文件**：保持结构清晰。
  3. **模块化目录设计**：例如 `pages/home`, `pages/ding` (打卡), `pages/mine`, `tools/` (工具类), `store/` (存储与状态), `types/` (类型定义)。

## 4. 阶段性开发计划 (AI 辅助开发 Roadmap)

为了高效、稳定地构建此 App，开发过程将拆分为以下五个迭代阶段：

### 阶段一：项目基础设施搭建 (Phase 1)
* [x] 梳理并创建合理的工程目录结构 (`pages`, `components`, `utils`, `viewmodel`, `database`)。
* [x] 编写 SQLite 数据库帮助类 (`RdbHelper`)，设计并执行建表语句。
* [x] 编写首选项帮助类 (`PreferencesUtil`)，用于轻量状态管理。

### 阶段二：伪登录与主框架 UI (Phase 2)
* [x] 开发**用户设置/选择页面**（伪登录）：输入昵称进入主页，保存用户信息。
* [x] 开发**App 主页框架**：使用 `Tabs` 组件搭建底部导航栏（包含三个 Tab：首页、打卡、我的），建立应用全局骨架。

### 阶段三：核心业务逻辑与数据绑定 (Phase 3)
* [x] 开发**首页 (Home)**：展示今日数据大盘（签到状态与日历、喝水进度与快捷加水、久坐活动次数、健康科普长列表）。
* [ ] 开发**首页增强 (Home Extra)**：加入微型周报趋势图、每日健康金句、喝水提醒智能状态栏。
* [ ] 开发**打卡页 (Check-in)**：实现各项健康打卡的快捷入口，以及用户自定义任务列表的渲染、新增、编辑、删除。
* [ ] **数据联调**：将首页和打卡页的 UI 操作与本地 SQLite 进行双向绑定，实现真实的数据读写。

### 阶段四：通知与提醒功能接入 (Phase 4)
* [ ] 封装代理提醒工具类，请求系统通知权限。
* [ ] 在“我的”页面添加提醒配置开关（自由设置喝水、久坐提醒的间隔与时间段）。
* [ ] 接入 `reminderAgentManager`，使设置的提醒生效。

### 阶段五：UI 动效与体验打磨 (Phase 5)
* [ ] 优化应用色彩搭配、间距和排版，使其符合现代高级 UI 审美。
* [ ] 在签到、打卡、任务完成时，添加生动的微交互动效 (Animations)。
* [ ] 进行功能自测，处理多用户切换等边界异常。
